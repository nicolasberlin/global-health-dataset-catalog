ALREADY PRESENT - DO NOT REIMPLEMENT
- Owner-scoped job/candidate reads and safe public error presenters.
- Explicit collection retry with ownership checks, atomic workload admission and
  protection against duplicate active collection. Reads do not enqueue work.
  Per-job retry cooldown/attempt caps are a separate policy decision (task 16).
- Persisted classification/collection queues, bounded consumers, automatic enqueue
  of online candidates, saved individual votes and latest-analysis restoration.
  Recovery intentionally supports ONE API process/instance; no worker leases.
- Versioned, data-preserving migrations and initialization checks cached per pool.
- Paginated catalog with database-side search/filters and lookup by dataset IDs.
- Three voters constructed through the same RCP client/factory, shared vote execution,
  model request timeouts, response-size limits and scoped vote fingerprint reuse.
- Frontend API client/workflow hooks and agreement filters derived from results.
- Landing-page fallback when structured candidates lack usable distributions.
- Consistent distribution/validation formats before persistence.
- Access status/reason, failed validation reports, DOI, licence and metadata provenance.
  These exist already; their interpretation and completeness can still improve.
- Validated-address HTTP connections, redirect checks, bounded network reads,
  container egress filtering and private PostgreSQL in production Compose.
- CI definitions for PostgreSQL, frontend, browser, container and proxy tests.
  Presence of CI configuration is not evidence that a particular release passed.
- Source-administration HTTP routes/UI removed; some legacy storage/worker code remains.
